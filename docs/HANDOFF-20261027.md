## 目标与用户最新决定

最终目标是 Dalamud 内独立窗口显示角色与真实粒子，同屏支持单素材、映射素材与组合，重播、停止、参数编辑后约 350ms 更新、相机控制，以及完整场景清理。游戏内需保存画面，切换 100 次和运行 30 分钟后检查持续资源增长。纯特效空场地属于后续 0.5。

用户最新选择是 **“暂不进入游戏，继续离线调查”**。本次没有启动游戏、加载开发插件或运行任何原生钩子。不要自动安排或运行游戏内测试；准备好可审查的验证步骤后再与用户约定时段。不得自动发布、修改游戏安装文件或在重启后续测。

## 本机工具与可复现操作

家中环境：.NET SDK 10.0.101；游戏版本文件 `2026.10.06.0000.0000`；Dalamud 15.0.3.9；FFXIVClientStructs 7.57.0.9602；Penumbra.Api 1.7.2.4。完整路径、其他依赖版本和构建参数见 [开发环境记录](DEVELOPMENT.md)。此电脑 EXE SHA-256 为 `958b78e278ad896493c484eb313ff605ab41edefef74f92b0ee078e69b281bf9`。另一台电脑必须重新核对 EXE 和 DLL，不能复用 RVA 或直接开启门槛。

```powershell
./scripts/Verify-Development.ps1 -Sqpack '本机游戏目录\game\sqpack'
```

脚本把构建、测试、环境摘要、真实素材编译和 PMP 检查结果放到 Git 忽略的 `artifacts/validation/home`，开发插件放到 `artifacts/plugin`。在另一台电脑没有 SqPack 时可不传参数，仍会构建插件/CLI 并运行测试。手动原生分析脚本 `scripts/Inspect-NativePreview.py` 依赖 capstone 和 pefile：

```powershell
python -m pip install --target artifacts/tools/python capstone pefile
python scripts/Inspect-NativePreview.py '本机游戏目录\game\ffxiv_dx11.exe' --references 9cd2d0 --references 9cd3e0
```

脚本仅读取 EXE；本机 DLL 的 ILSpy 导出文件、反汇编、原始游戏资源、PMP、日志和完整构建都在被忽略的 `artifacts`。另一台电脑重新生成，不要把游戏资源、转储或带资源的包推到公开 GitHub。ILSpy 本机工具版本 11.1.0.9782、capstone 5.0.9、pefile 2024.8.26，均安装在本机被忽略目录，不要求使用相同工具版本。

## 已核对事实与边界

精确 RVA、指令和复现方式见 [本机二进制证据](NATIVE-BINARY-20261027.md)：ActorVFX 创建返回 0x1E0 包装对象；CharaView Dtor 不调用 Release；Initialize 会直接删除目标 ClientObject 并创建新载体，不是槽位申请接口；自动角色分配只扫描 0–239，视图使用 240–247；显式创建不能当作独占租约。CharaView 将相机绑定到角色及武器模型，ActorVFX 取得模型的视图编号。该编号在后续特效上下文中被读取，但最终粒子、透明和深度输出仍未证实。

本机 Dalamud 的 Update 在游戏 Framework Tick 钩子线程执行，`RunOnFrameworkThread` 在 Framework 销毁后可能直接执行调用者回调。已加创建/停止入口线程前置检查，但原生析构可能从其他线程发生，游戏卸载与插件卸载顺序仍需证明。调用观察器只能补充有限的运行证据，不能自动批准所有权、安全性或画面验收。
