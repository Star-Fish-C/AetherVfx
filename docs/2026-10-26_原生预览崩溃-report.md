# AetherVfx 原生预览崩溃与保护措施

2026-10-26 的原生验证导致 FF14 客户端退出。崩溃栈明确位于本插件新增的 `NativeVfxEngine.Describe()`，不是已经证明安全的预览路径。0.3.3 禁用全部原生预览和探针启动，移除了资源内部指针遍历，并取消任何加载后自动续测。独立播放器计划的第一阶段未通过，不交付功能完成版。

## 范围与环境

范围是用户授权的本机 AetherVfx 开发和游戏内验证。后台验证未修改游戏文件或发布 Mod。

- 客户端版本文件：`2026.10.06.0000.0000`。
- Dalamud：`15.0.3.9`；FFXIVClientStructs：`7.57.0.9602`。
- 崩溃进程：48376；发生时间：2026-10-26 15:39（Asia/Shanghai）。
- 验证样本：`vfx/common/eff/dk10ht_wra0c.avfx`。

调用路径：用户已授权的原生验证 → 本地角色原始路径对照 → 每帧预览 Tick → 一秒后的资源诊断 → 沿 VFX 内部资源指针读取 → 访问违规 → CLR 终止进程。

## 已实施保护

- 用统一 `NativePreviewSafety` 默认关闭原生功能，拦截特效创建、独立视图初始化及探针入口。
- 删除加载后自动测试的编译开关及运行逻辑；用户重启后不会自动继续验证。
- `Describe()` 只输出已跟踪的不透明句柄，不再解引用原生资源指针。非零和登记在 HashSet 中均不作为内存有效性证明。
- 预览操作显示停用原因，不再因预期停用而反复记录错误通知；目录、工程和导出逻辑保留。
- 添加视图索引／槽位边界及原生停用保护回归测试；自动测试不能替代原生安全性和图像验收。

## 恢复原生开发前必须完成

1. 离线核对当前客户端的 ActorVFX 返回对象 ABI、销毁路径与线程时序，确认结构偏移及所有权，不能依靠特征码匹配成功推定兼容。
2. 将资源加载诊断改为经过验证的托管事件或具有可靠生命周期保护的接口；不能再次直接遍历未经验证的内部资源指针。
3. 单独确认共享视图载体、相机和渲染目标的申请／释放协议，解决初始化和槽位争用，禁止以预分配对象非空或模型暂未加载作为唯一所有权依据。
4. 另行约定游戏内验证时段，再执行最小样本；通过后才恢复模型隐藏、四类特效、连续切换和长时间循环测试。

当前没有粒子图像、独立渲染成功、100 次切换或 30 分钟运行的通过记录。后续工作继续以这些验收条件为准。
