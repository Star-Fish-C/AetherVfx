## 可重复的验证

在仓库根目录：

```powershell
./scripts/Verify-Development.ps1 -Sqpack 'G:\FF14\本体\最终幻想XIV\game\sqpack'
```

脚本输出 `artifacts/validation/home`（日志、版本、哈希），`artifacts/samples`（本机样本），`artifacts/plugin`（完整开发文件）。这些目录均不提交 Git。换电脑后仅替换 SqPack 路径，并确认 Dalamud 和 Penumbra 的依赖位置。

## 本轮实际变更

- 删除独立适配器中先初始化 5–7 号共享视图槽、再猜测占用情况的代码，以及原生 SRV 回读路径。
- 预览会话提供停用、空闲、初始化、播放中和失败状态；租约逆序释放、会话代次拒绝过期结果，清理失败时禁止继续启动。
- 会话模型只能接收真正拥有的资源租约。当前没有已验证的原生视图分配器，不能把托管测试当作实际资源管理验收。
- 独立窗口默认入口、角色同屏目标与不持久化实验开关；兼容检查独立于实验开关。
- 自动串行探针改为单项手动命令；禁用状态下记录拒绝原因。移除旧的自动切样、真实角色对照和隐藏载体测试。
- 修正参数更新合并使用最后一次编辑时间；禁止启动失败后仍打开自动更新。
- 保留工程 v2、现有 CLI/PMP 格式、装备与目录功能，不发布、不修改游戏文件。

## 当前门槛与下一步

追加实现：NativeVfxEngine 已接收 IFramework，在实际创建／销毁调用前检查框架线程；框架卸载后拒绝新建。停止操作被拒绝时，PreviewManager 保留 effect 和 Penumbra 映射以便正确重试，不提前丢弃句柄。插件重新构建通过（0 警告、0 错误），完整文件已更新到 artifacts/plugin。这只是执行前置条件；当前尚未实现跨线程请求调度、游戏退出前清理及原生析构线程的证明，因此兼容门槛仍未通过。

阶段一已完成。阶段二已核对本机 ActorVFX 创建参数、返回对象大小及 CharaView 部分生命周期；仍缺销毁线程、槽位独占申请与交还，以及最终粒子渲染通道证据。参见 [兼容调查](NATIVE-COMPATIBILITY.md) 和 [本机二进制核验](NATIVE-BINARY-20261027.md)。因此阶段三只交付托管基础设施和状态入口；真实视图、相机、粒子及原生资源租约均未接通。阶段四游戏内验收和 0.5 空场地未开始。

下一位开发者先取得可核验的当前客户端接口／生命周期证据；不要直接把 Compatibility 的五项布尔量改为 true。确认协议后才能实现原生后端，再另行约定游戏验证时段，先测角色视图，再测单个原始光环。若 CharaView 不包含粒子通道，另行设计接入方式，不继续堆叠空场地功能。
